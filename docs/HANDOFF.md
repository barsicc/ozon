# Перенос проекта

Для новой рабочей копии достаточно клонировать репозиторий и установить Python 3.12. Данные, схемы, инструкции, зависимости и GitHub Actions хранятся в Git. Исходный SingleFile HTML (~470 МБ) и доступ к Ozon Job нужно переносить отдельно. После клонирования запусти `python3 tools/audit_dataset.py` или `py -3.12 tools/audit_dataset.py` на Windows.

## Пересборка данных

В отдельной рабочей копии запусти команды из корня репозитория. Папку рабочей выгрузки лучше расположить за пределами репозитория. Используй Python из окружения, описанного в README.

```text
python -I tools/strip_images.py <source.html> <work_dir>
python -I tools/parse_stores.py <work_dir>
python -I tools/build_dataset.py <work_dir>
python tools/audit_dataset.py
```

Команда build_dataset.py перезаписывает `data/darkstores.json` и генерирует JPEG в `images/schemes/`. Перед коммитом проверь diff и сравни результат с предыдущей версией. Если в базе уже есть координаты, сравни их отдельно: сборщик создаёт записи заново. Сведения о расхождениях добавляй в отчёт вместе с подтверждающим источником.

## Ozon Job на Windows 11

На Android уже включена отладка по USB. На подключённом и разблокированном телефоне подтверди разрешение отладки. Если ADB ранее использовался на компьютере, в PowerShell можно найти путь к уже запущенному экземпляру:

```powershell
Get-Process adb -ErrorAction SilentlyContinue | Select-Object -ExpandProperty Path
```

Если путь найден, вызови `& "C:\полный\путь\adb.exe" devices -l`. Статус `device` означает, что телефон готов. При `unauthorized` подтверди запрос на телефоне. Если исполняемого файла нет, его можно распаковать из официального архива [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools).

Сначала проверить доступность текста на одной открытой карточке. Ниже `adb` означает команду в PATH или вызов по полному пути.

```text
adb shell uiautomator dump /sdcard/ozon-card.xml
adb pull /sdcard/ozon-card.xml .
```

Проверить, видны ли в XML название, адрес и «Как добраться». Для изображения и отсутствующих полей сохранять скриншоты карточки и прокручивать до конца инструкции. После пилота на 3–5 складах можно автоматизировать обход регионов через UI Automator или Appium. Сохранять регион, название, адрес, полный маршрут, дату и снимки. При сверке не считать отсутствие в одной выгрузке доказательством закрытия. Сборщик ещё предстоит проверить на подключённом телефоне.

## Геокодирование и публикация

- `YANDEX_MAPS_API_KEY` уже добавлен в GitHub Secrets по словам владельца. Успешный вызов Яндекса из Actions пока не подтверждён. Если репозиторий переносится в другой GitHub-репозиторий, секрет надо добавить там отдельно.
- `geocode.yml` запускается вручную и автоматически при изменениях заданных файлов в `darkstores-data`. Он записывает координаты, кеш и отчёт, затем коммитит и пушит их в выбранную ветку. Для первой проверки используй отдельную ветку и проверь отчёт по точности и региону.
- Для сайта запланирован GitHub Pages. Сначала собрать мобильный каталог с поиском, адресами, карточками и копированием. Затем добавить карту, кластеры, геопозицию и список ближайших после проверки координат. Две известные ошибочные схемы следует скрыть до замены.
- Публикацию сайта настроить отдельным workflow после появления сайта. Для браузерной карты предусмотреть отдельный ключ с ограничением по домену. Перед публикацией проверить условия показа карт, хранения координат и использования изображений.
